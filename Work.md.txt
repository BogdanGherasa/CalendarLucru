# SPEC: Time-Blocker & Notes — v1.0 (MVP)

## 0. Stack tehnologic

| Strat | Tehnologie | Versiune |
|---|---|---|
| Runtime | .NET | 10 (LTS) |
| Backend | ASP.NET Core: Razor Pages (pagini) + Minimal API (JSON pentru CRUD) | 10.0.x |
| Autentificare | ASP.NET Core Identity, cookie auth, pagini proprii (fără pachetul Identity.UI) | 10.0.x |
| ORM | Entity Framework Core | 10.0.x |
| Bază de date | SQLite (`App_Data/timeblocker.db`) | — |
| Frontend | HTML5 (Razor), CSS3, Bootstrap 5.3.x (CDN jsDelivr + `integrity`), JavaScript vanilla (ES modules) | — |
| Teste | xUnit + SQLite in-memory | — |

### Presupuneri (decise de arhitect, modificabile)
- P1: Orele sunt stocate ca oră locală (`DateOnly` + `TimeOnly`), fără conversie de fus orar. Ziua curentă este determinată de browser și trimisă explicit ca `?date=YYYY-MM-DD`.
- P2: Un time-block nu poate trece de miezul nopții (`EndTime > StartTime`, aceeași zi).
- P3: Suprapunerile de intervale pentru același utilizator și aceeași zi sunt RESPINSE (HTTP 409).
- P4: Fără confirmare email și fără resetare parolă în v1.0.
- P5: „Timp real” = operațiile CRUD actualizează timeline-ul fără reîncărcarea paginii (fetch + re-randare). Fără WebSockets/SignalR.

### T04 — Configurare aplicație
**Fișiere:** `src/TimeBlocker.Web/Program.cs`, `src/TimeBlocker.Web/appsettings.json`, `src/TimeBlocker.Web/appsettings.Development.json`

**Dependențe:** T03, T07, T08 (înregistrările pot fi adăugate incremental)

- `AddAntiforgery(o => o.HeaderName = "X-CSRF-TOKEN")`.
- DI: `AddScoped<ITimeBlockService, TimeBlockService>()`.
- Pipeline: `UseHttpsRedirection`, `UseStaticFiles`, `UseRouting`, `UseAuthentication`, `UseAuthorization`, `MapRazorPages`, `MapTimeBlockEndpoints()`.

### T06 — Validare
**Fișiere:** `src/TimeBlocker.Web/Validation/TimeBlockValidator.cs`

**Dependențe:** T05

**Logică:**
- Clasă statică, metodă `Validate(TimeBlockUpsertDto dto, out ParsedTimeBlock parsed)` → returnează `Dictionary<string, string[]>` cu erori (format compatibil `Results.ValidationProblem`).
- Reguli:
  - `Title`: trim; obligatoriu; 1–120 caractere.
  - `Date`: parsare exactă `yyyy-MM-dd` cu `CultureInfo.InvariantCulture`.
  - `StartTime`, `EndTime`: parsare exactă `HH:mm`; minute permise doar multipli de 5.
  - `EndTime > StartTime` (P2). Durată minimă 5 minute.
  - `Notes`: opțional; trim; string gol → `null`; max 5000 caractere.
- `ParsedTimeBlock`: record intern cu tipurile tari (`DateOnly`, `TimeOnly`) și titlul/notițele normalizate.
- Cheile erorilor: numele câmpurilor în camelCase (`title`, `date`, `startTime`, `endTime`, `notes`).

### T07 — Serviciu de business
**Fișiere:** `src/TimeBlocker.Web/Services/ITimeBlockService.cs`, `src/TimeBlocker.Web/Services/TimeBlockService.cs`, `src/TimeBlocker.Web/Services/ServiceResult.cs`

**Dependențe:** T03, T06

**Logică:**
- `ServiceResult<T>`: stare `Success | NotFound | Conflict | Invalid`, payload `T?`, erori `Dictionary<string,string[]>?`.
- Toate metodele primesc explicit `string userId`; TOATE interogările filtrează după `UserId` (izolare între utilizatori).
- Metode:
  - `GetByDateAsync(userId, DateOnly date)` → listă sortată după `StartTime`, `AsNoTracking`.
  - `GetByIdAsync(userId, id)` → `NotFound` dacă nu există SAU aparține altui utilizator (nu se distinge, anti-enumerare).
  - `CreateAsync(userId, ParsedTimeBlock)` → verifică suprapunere; `Conflict` dacă există.
  - `UpdateAsync(userId, id, ParsedTimeBlock)` → `NotFound` / verifică suprapunere excluzând propriul `Id` / salvează.
  - `DeleteAsync(userId, id)` → `NotFound` sau șterge.
- Regula de suprapunere (P3): există alt block al aceluiași user, aceeași `Date`, cu `existing.StartTime < new.EndTime && existing.EndTime > new.StartTime`. Capetele care se ating (10:00–11:00 și 11:00–12:00) NU sunt suprapunere.
- Mesaj de conflict: include titlul și intervalul block-ului cu care se suprapune.

### T08 — API REST
**Fișiere:** `src/TimeBlocker.Web/Endpoints/TimeBlockEndpoints.cs`, `src/TimeBlocker.Web/Endpoints/AntiforgeryValidationFilter.cs`

**Dependențe:** T07

**Logică:**
- Metodă de extensie `MapTimeBlockEndpoints(this IEndpointRouteBuilder)`; grup `/api/timeblocks`, `.RequireAuthorization()`.
- `userId` se obține exclusiv din `UserManager.GetUserId(ClaimsPrincipal)`; niciodată din body/query.
- Rute:

| Metodă | Rută | Succes | Erori |
|---|---|---|---|
| GET | `/api/timeblocks?date=yyyy-MM-dd` | 200 + `TimeBlockResponseDto[]` | 400 dacă `date` lipsește/invalid |
| GET | `/api/timeblocks/{id:int}` | 200 + `TimeBlockResponseDto` | 404 |
| POST | `/api/timeblocks` | 201 + `Location` + DTO | 400 (ValidationProblem), 409 |
| PUT | `/api/timeblocks/{id:int}` | 200 + DTO | 400, 404, 409 |
| DELETE | `/api/timeblocks/{id:int}` | 204 | 404 |

- 409 returnat ca `ProblemDetails` cu `detail` = mesajul de conflict.
- `AntiforgeryValidationFilter : IEndpointFilter`: pentru POST/PUT/DELETE apelează `IAntiforgery.ValidateRequestAsync`; la eșec → 400. Aplicat pe grup. (Necesar deoarece autentificarea e pe cookie și body-ul este JSON, nu formular.)

### T13 — Randare timeline (JS)
**Fișiere:** `src/TimeBlocker.Web/wwwroot/js/timeline.js`

**Dependențe:** T12

**Logică:**
- Scală: 1 minut = 1px (o oră = 60px, ziua = 1440px). Valoarea scalei într-o constantă unică.
- `render(container, blocks)`: șterge block-urile existente; pentru fiecare block creează element absolut poziționat: `top = minuteStart`, `height = max(durată, 20)`. Afișează titlul și intervalul `HH:mm–HH:mm`; dacă înălțimea ≥ 45px afișează și primul rând din notițe (trunchiat).
- Tot textul se inserează cu `textContent` (fără `innerHTML` pentru date de utilizator — protecție XSS).
- Click pe block → emite eveniment custom `block:select` cu `id`.
- Click pe zonă goală a timeline-ului → emite `slot:select` cu ora rotunjită în jos la 30 min (pre-completează formularul de adăugare, durată implicită 60 min, limitată la 23:59).
- Linia orei curente (roșie) vizibilă doar când data afișată = ziua curentă din browser; actualizată la fiecare 60s.
- La încărcarea zilei curente: scroll automat la (ora curentă − 1h).
- Funcție utilitară `linkify(text)` → `DocumentFragment`: text simplu cu `TextNode`, iar URL-urile `http(s)://` devin `<a target="_blank" rel="noopener noreferrer">`. Alte scheme (ex: `javascript:`) NU se transformă în link.

### T14 — Formular modal (JS)
**Fișiere:** `src/TimeBlocker.Web/wwwroot/js/modal.js`

**Dependențe:** T12, T13

**Logică:**

## 3. Criterii de acceptanță MVP
1. Un utilizator nou se poate înregistra, autentifica și deconecta.
2. Accesul neautentificat la `/` redirecționează la Login; la `/api/*` returnează 401.
3. Pe dashboard, ziua curentă este afișată ca timeline 00:00–24:00 cu linia orei curente.
4. Se pot adăuga, vizualiza, edita și șterge intervale (titlu, oră start/sfârșit, notițe) fără reîncărcarea paginii.
5. Linkurile din notițe sunt clickabile și se deschid în tab nou; niciun conținut de utilizator nu este interpretat ca HTML.
6. Utilizatorul A nu poate vedea sau modifica în niciun fel datele utilizatorului B.
7. Interfața este utilizabilă pe un ecran de 375px lățime.
8. `dotnet build` și `dotnet test` trec fără erori și fără avertismente de nullability.
